# Skill: kb-organize


## 原文链接

- 原文缺失待核查：`raw/sources/.../original.md`
- 原文缺失待核查：`raw/sources/.../original.pdf`
- 原文缺失待核查：`raw/sources/.../transcript.md`

## 触发条件

当需要整理本地知识库、归档已入库文章、处理孤立文件、拆分原文与笔记、规范标题、合并重复概念、刷新索引或生成迁移清单时使用。适用于 `整理知识库`、`归档原文`、`处理收件箱`、`整理已入库文章`、`合并文章笔记`、`修复孤立页`、`刷新知识库目录` 等任务。

## 目标

把已经进入 vault 的内容整理为可持续维护的 LLM Wiki：

- 原文是证据层，按来源归档，保持不可变。
- 来源页记录一份来源说了什么，一份来源只对应一个主来源页。
- 知识页按概念、实体和综合结论沉淀，不按文章逐篇建页。
- 所有正式知识内容必须同时具备来源页回链和原文跳转链接。
- 目录表达页面类型，主题关系通过双向链接、topics/tags 和 maps 表达。
- 所有变更可追溯、可逆、可重复执行。

## 强制边界

1. 开始前读取当前范围内的 `AGENTS.md`、`README.md`、模板、索引和最近日志；现有明确规范优先于本 skill。
2. 修改前记录 `git status`；修改后报告 `git diff --stat`。禁止自动提交和推送。
3. 不自动删除文件。重复项、临时文件、旧页面只能记录、重定向、归档候选或进入复核清单。
4. 不改写、覆盖或摘要替换 raw 原文。移动原文时必须校验移动前后哈希一致。
5. 证据不足时只写阶段性结论或复核项，不把推断写成事实。
6. 所有知识内容必须有原文跳转链接；只链接到来源页不达标。链接应指向 raw 原文、PDF 页码、正文标题锚点、网页快照锚点或转写时间戳。若原始文件因脚本依赖暂未迁入 raw，必须链接到已登记原始文件并写明待迁移原因。
7. 无法定位原文跳转位置的内容只能写入来源页的 `待验证项` 或复核清单，不能写入正式知识结论。
8. 整理必须幂等：再次运行不能重复创建同一个来源页、知识页或日志条目。
9. 不处理采集、RAG、Embedding、向量数据库、搜索系统、模型部署或业务代码修改。

## 参数约定

未指定时使用当前工作目录：

```text
KB_ROOT=<知识库根目录>
SCOPE=all | <目录或文件列表>
MODE=apply | plan
BATCH_SIZE=20
RAW_DIR=raw
WIKI_DIR=知识库
LANGUAGE=zh-CN
```

`MODE=apply` 时先审计，再执行低风险、可逆修改；无法判断的文件写入复核清单，不阻塞其他安全整理。

## 页面分层

```text
raw-source     原文、PDF、网页快照、逐字稿、附件
source-note    单一来源的摘要、摘录、批注和证据地图
concept        稳定概念、方法或可复用知识
entity         人物、组织、产品、项目
synthesis      跨来源比较、结论、时间线、决策
question       未解决问题
mixed          原文、摘要、批注或多个概念混杂
unknown        无法可靠判断
```

## 标题与 ID

必须区分三种名称：

| 名称 | 用途 | 规则 |
|---|---|---|
| `original_title` | 作者原始标题 | 原样保存，不规范化、不覆盖 |
| `title` | 阅读用显示标题 | 可规范化为清晰标题 |
| 文件名或 `id` | 稳定机器标识 | 不因标题润色频繁变化 |

命名规则：

- 来源 ID：`src-<发布日期或采集日期>-<作者或机构>-<短标识>`。
- 概念页使用标准名词，如 `上下文工程`。
- 实体页使用正式名称，如 `OpenAI`。
- 综合页使用明确比较、问题或结论。
- 同义词写入 `aliases`，不要创建重复页面。
- 标题为 `一些想法`、`读后感`、`文章笔记`、`总结2`、`新版整理`、`未命名` 的页面必须进入复核或重命名候选。

## 执行流程

### 1. 审计现有约定

- 查看两到三层目录树。
- 读取规则文件、模板、索引和最近日志。
- 抽样读取 raw 原文、来源页、概念页、综合页和收件箱文件。
- 识别 frontmatter、链接格式、附件规则、归档规则和现有索引习惯。

### 2. 建立全量清单

扫描 `SCOPE`，将文件分类为上面的八类，并生成或追加：

```text
<WIKI_DIR>/_meta/content-inventory.md
<WIKI_DIR>/_meta/migration-plan.md
```

清单至少包含：

- 原始路径
- 当前标题
- 文件类型
- 是否包含完整原文
- 是否包含个人批注或 AI 总结
- 原始链接、作者和日期
- 原文跳转链接或待定位原因
- 建议 `source_id`
- 重复候选
- 建议合并到的知识页
- 目标路径
- 风险和待确认项

### 3. 整理原文和来源页

对每份来源：

1. 确定或复用稳定 `source_id`。
2. 保存 `original_title`，不得被规范化标题覆盖。
3. 原文优先命名为 `original.md`、`original.pdf`、`snapshot.html` 或 `transcript.md`。
4. 原文目录不承担主题分类。
5. 移动原文时校验哈希；哈希不一致必须停止该文件迁移并写入复核清单。
6. 不自动删除重复原文，只记录重复关系。
7. 创建或更新唯一来源页，包含来源元数据、一句话摘要、作者核心观点、证据地图、个人批注、待验证项、影响的知识页、原文路径和可点击的原文跳转链接。
8. 证据地图中的每条证据必须尽可能指向原文位置：Markdown 标题锚点、PDF 页码、HTML 锚点或音视频转写时间戳。

### 4. 沉淀知识

对每份来源识别六类知识增量：

```text
新增    此前没有的长期知识
加强    给已有结论增加证据
修正    新来源改变已有表述
冲突    来源之间存在分歧
案例    只用于说明
待验证  证据不足
```

执行顺序：

1. 搜索现有页面、aliases 和同义词。
2. 优先更新已有知识页。
3. 把文章特有语境保留在来源页。
4. 只把可复用、可独立查询的内容写入知识页。
5. 知识页的关键陈述必须同时具备两类链接：来源页回链和原文跳转链接，并尽可能标注章节、页码、时间戳或锚点。
6. 证据格式优先使用：`陈述 — [[知识库/sources/src-id|来源页]]；原文：章节（原文缺失待核查：`raw/sources/.../original.md`）`。PDF 使用 `p.12（原文缺失待核查：`raw/sources/.../original.pdf`）`；转写使用 `00:03:21（原文缺失待核查：`raw/sources/.../transcript.md`）`。暂未迁入 raw 的原始文件可链接当前登记路径，但必须列入待迁移项。
7. 同一概念分散在多篇文章笔记中时，合并到一个主知识页。
8. 旧页面不得直接删除，先转换为重定向、归档候选或复核项。
9. 来源相互冲突时，保留双方观点、证据、日期和各自原文跳转链接，不擅自消解。

只有满足至少一个条件才创建独立知识页：

- 会被独立检索或反复使用。
- 被两个及以上来源支持。
- 属于领域中的标准概念、实体或方法。
- 与多个页面形成稳定关系。
- 对实践、解释或决策有长期价值。

不要为一次性案例、单篇文章修辞、未验证信息或同义词创建新概念页。

### 5. 处理孤立文件

从 `kb-audit`、lint 输出或全量清单中获取孤立文件后，先判断原因：

| 原因 | 处理方式 |
|---|---|
| 有内容但无索引 | 写入合适 index 或地图页 |
| 放在 vault 根目录 | 优先改为兼容入口或写入迁移计划；需要移动时先给出路径映射和回滚方式 |
| 重复内容 | 记录重复关系，保留主页面，副本转复核项或重定向候选 |
| 临时文件 | 写入复核清单；没有用户确认不得删除 |
| raw 原文未登记 | 建立来源页并记录哈希 |

孤立文件处理必须保留：

- 原路径到目标路径映射。
- 每个文件处理原因。
- 更新的 index 或 maps diff。
- 无法判断项的复核记录。

### 6. 整理目录和导航

优先适配现有结构。若现有结构缺失或明显混乱，使用最小类型目录：

```text
raw/
  inbox/
  sources/
知识库/
  sources/
  concepts/
  entities/
  syntheses/
  questions/
  maps/
  _meta/
  _review/
```

规则：

- 目录只表示页面类型。
- 不按唯一主题建立深层目录。
- 避免超过两层主题嵌套。
- 页面属于多个主题时，用链接、topics/tags 和 maps 表达。
- 移动页面后修复内部链接；无法安全修复时保留重定向说明或写入复核清单。
- 更新现有 index/MOC；没有时创建最小入口页。

### 7. 验证

完成批次前检查：

- 原文移动前后哈希是否一致。
- 是否存在重复 `source_id`。
- 是否存在重复页面 ID。
- 是否存在断链和孤儿页。
- 是否存在无来源支持或无原文跳转链接的知识陈述。
- 是否存在只链接来源页、但无法跳到原文位置的知识陈述。
- 是否存在重复 aliases。
- `original_title` 是否完整保留。
- 每份来源是否只有一个主来源页。
- 是否有文件被误删。
- 再次运行是否会重复创建页面。

生成或追加：

```text
<WIKI_DIR>/_meta/distillation-log.md
<WIKI_DIR>/_review/unresolved-items.md
```

## 自动化辅助

若仓库存在 `tools/kb_full_distill.py`，优先使用它生成全量清单、来源页索引、迁移计划、沉淀日志和复核清单。运行后必须人工抽查输出，不能把脚本分类结果直接当作最终判断。

## 输出要求

完成后只报告：

1. 扫描数量和实际处理数量。
2. 创建、更新、移动、合并候选和未处理数量。
3. 本批次形成或更新的知识页。
4. 原文哈希、来源页回链和原文跳转链接检查结果。
5. 需要人工决定的歧义项。
6. `git diff --stat` 和关键变更摘要。

不要复述方法论，不要自动提交 Git。
