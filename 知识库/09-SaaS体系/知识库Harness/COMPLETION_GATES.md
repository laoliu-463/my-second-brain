# Knowledge Base Completion Gates

## Harness Engineering 工程化门禁（统一基线）

每个 Gate 都遵循 `Plan -> Do -> Check -> Act` 与 `输入-变更-验证-回退` 四段式交付格式。  

通用输出模板（所有 Gate 共用）：

- **输入**：触发任务 ID、来源路径、依赖链（源头 -> 影响 -> 结果）。
- **变更**：文件清单（含旧路径/新路径）、边界判断、最小单元拆分记录。
- **验证**：脚本输出、人工审阅结论、失败项处理。
- **回退**：失败时的下一位状态（回退到任务前状态或 manifest 路径）。

## Gate 0 — 扫描完成

**适用场景**：巡检、审计、摸底（只读不修改）

**必须输出**：
- 总文件数、分类分布
- 孤立文件清单（路径 + 大小 + 原因）
- 空文件/stub 清单
- 重复内容清单

**通过条件**：清单完整、分类准确、无遗漏

---

## Gate 1 — 修改完成

**适用场景**：文件迁移、归类整理、index 更新

**必须输出**：
- 修改文件清单（原路径 → 新路径）
- 每个文件移动/修改的原因
- 更新后的 index.md 相关条目

**通过条件**：目标位置正确、index 已同步、无 broken links

---

## Gate 2 — 删除完成

**适用场景**：GC 清理空文件、重复文件、临时文件

**必须输出**：
- 删除清单（路径 + 大小 + 删除原因）
- 已备份记录（移动到 archive 目录的路径）
- 删除前的原始内容摘要（防止误删有价值的）

**通过条件**：无知识价值文件被误删、受保护文件未被触碰

---

## Gate 3 — 新建完成

**适用场景**：新建分类入口、新建知识条目

**必须输出**：
- 新文件路径和内容摘要
- 归属分类理由
- 对应 index.md 条目

**通过条件**：分类正确、内容非空、不与现有重复

---

## Gate 4 — 批量归档完成

**适用场景**：大规模迁移 raw/sources/ 内容

**必须输出**：
- 迁移清单（原 → 新）
- 新分类 index.md 完整更新
- 未处理清单（延期原因）

**通过条件**：所有有价值的文件已归类、孤立文件 < 5

## Gate 5 — 工程化复盘（建议）

**适用场景**：多任务串行/并行后统一回顾

**必须输出**：
- 违例清单：依赖链断裂、重复源、覆盖冲突
- 根因类型：流程缺陷 / 知识结构缺陷 / 证据缺失
- 下次优化计划：本轮新增规范或工具需求（如有）

**通过条件**：有可执行改善项，且在 `01-状态/待确认问题.md` 显式登记。

---

## 禁止事项（所有 Gate 通用）

- 不确认不删除：未读懂内容前不删除
- 不重复：创建前必须 `rg` 确认无重复
- 不裸建：新建文件必须有对应 index 条目
