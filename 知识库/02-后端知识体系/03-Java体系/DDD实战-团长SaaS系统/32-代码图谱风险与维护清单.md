## 维护清单

| 场景 | 必查证据 | 最小验证 |

| 改 real-pre 配置 | `docker-compose.real-pre.yml`、`.env.real-pre.example`、部署文档、release 报告 | preflight、health、P0、roles、日志 |
| 改 test 造数 | `TestDataService`、`/api/test/seed`、E2E fixtures | seed/reset 后跑对应 P0 子集 |

## 风险处理原则

- 不因为类大就直接重构；先确认变更目标、测试覆盖、调用路径和回滚方式。
- 对高连接节点的修改必须拆成“最小改动 + 最小回归”，避免一次性跨商品、订单、寄样、权限多域修改。
- 图谱提示的是影响范围，不是根因；真实缺陷仍需日志、接口响应、数据库事实和测试结果证明。
- 对 `real-pre` 链路，缺真实 Token、真实订单、真实上游响应时只能写 `PENDING` / `BLOCKED`。
