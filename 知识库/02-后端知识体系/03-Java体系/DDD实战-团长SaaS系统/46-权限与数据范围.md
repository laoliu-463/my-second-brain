# 权限与数据范围

## 概述

用户域统一提供 `self/group/all` 数据范围，业务域不得自行发明数据范围语义。V1 以当前权限注解、后端查询过滤和 E2E 验证为主。

## 数据范围定义

| 范围 | 含义 | 典型使用 | 验收方式 |
| --- | --- | --- | --- |
| `self` | 仅当前用户负责的数据 | 渠道个人商品、达人、订单、寄样 | 不同账号比对列表 |
| `group` | 当前组织或团队范围 | 主管查看组内订单、业绩 | 组织维度 API/SQL 比对 |
| `all` | 管理员或授权全量范围 | 管理端看板、审计、配置 | 管理员账号 E2E |

## 模块接入要求

| 模块 | 接入要求 | 风险 |
| --- | --- | --- |
| 商品域 | 列表、转链、映射查询按数据范围过滤 | 越权看到他人商品或映射 |
| 达人域 | 达人资料、跟进、地址按角色和组织过滤 | 越权查看达人隐私 |
| 寄样域 | 申请、审批、发货权限分离 | 越权审批或修改状态 |
| 订单域 | 订单事实查询按数据范围过滤 | 越权查看订单事实 |
| 业绩域 | 业绩明细和汇总按数据范围过滤 | 越权查看提成和归属 |
| 分析模块 | dashboard 根据当前用户范围读汇总 | 看板越权 |
| 配置域 | 配置修改需要管理权限，读取按业务需要开放 | 低权限修改规则 |

## 验证清单

- 至少使用管理员、主管、普通渠道账号验证同一 API 返回差异
- E2E 覆盖登录后菜单、列表数据、操作按钮和越权错误提示
- 后端测试或 SQL 证据能证明过滤条件生效
- 不用前端隐藏按钮替代后端权限校验

## 技术实现

- `@RequireRoles` 注解控制角色权限
- `@DataScope` 注解控制数据范围过滤
- Spring Security Filter 链统一鉴权
- MyBatis-Plus 拦截器实现 `self/group/all` SQL 注入
