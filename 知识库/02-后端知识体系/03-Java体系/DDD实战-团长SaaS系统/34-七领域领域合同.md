# 七领域领域合同

## 概述

系统按职责分为七个领域 + 一个分析模块，各领域通过事件契约交互。核心原则：订单域只存事实，业绩域负责最终归属，分析模块只读汇总。

## 七领域 + 分析模块

| 领域 | 职责 | 禁止越界 |
| --- | --- | --- |
| [[DDD实战-团长SaaS系统/34a-用户域合同|用户域]] | 账号、角色、组织、`self/group/all` 数据范围 | 不计算业务归属 |
| [[DDD实战-团长SaaS系统/34b-配置域合同|配置域]] | 配置事实、规则参数、配置审计 | 不执行具体业务规则 |
| [[DDD实战-团长SaaS系统/34c-商品域合同|商品域]] | 活动商品、商品库、转链、`pick_source_mapping` | 不计算提成 |
| [[DDD实战-团长SaaS系统/34d-达人域合同|达人域]] | 达人资料、标签、地址、渠道关系 | 不替代订单归属 |
| [[DDD实战-团长SaaS系统/34e-寄样域合同|寄样域]] | 寄样申请、审批、发货、交作业状态 | 不直接判定业绩 |
| [[DDD实战-团长SaaS系统/34f-订单域合同|订单域]] | 订单事实、退款事实、归因输入 | 不算提成、不应用独家覆盖 |
| [[DDD实战-团长SaaS系统/34g-业绩域合同|业绩域]] | 最终归属、提成、冲正、双轨金额计算 | 不采集第三方事实 |
| [[DDD实战-团长SaaS系统/34h-分析模块合同|分析模块]] | 只读汇总、报表、看板 | 不重算业绩归属 |

## 领域依赖关系

```
商品域 pick_source_mapping → 订单域 → 业绩域 → 分析模块
达人域 ─────────────────────────────→ 寄样域 → 订单域
配置域 ─────────────────────────────────────→ 业绩域
用户域 ──→ 所有业务域（提供数据范围）
```

## 事件模式

- V1 以 Spring 本地事件、事务边界内外处理和已存在 Outbox 记录为可执行口径
- 事件总表先记录生产者、消费者、触发条件、幂等键和证据，不要求全部 MQ 化
- 跨服务拆分、MQ、事件重放和事件版本治理放入后续阶段

## 架构决策

| ADR | 核心结论 |
| --- | --- |
| ADR-001 | 模块化单体，不引入 FastAPI / Celery / Python |
| ADR-003 | 订单域只存事实，不计算提成 |
| ADR-004 | 业绩域负责最终归属、提成、冲正 |
| ADR-005 | 分析模块只读汇总，不重算归属 |
