# 业务闭环总览

## 概述

抖音团长 SaaS 的核心价值是"流量分发有闭环，业绩归因有回流"。商品通过转链形成可推广商品，达人通过寄样建立合作关系，订单通过 `pick_source` 回流后由业绩域计算最终归属，形成完整的业务闭环。

## 总体闭环

```
商品域：活动商品 → 转链 → pick_source_mapping
                ↓
达人域：达人资料 → 标签 → 地址 → 渠道关系
                ↓
寄样域：申请 → 审批 → 发货 → 订单已同步事件 → 交作业完成
                ↓
订单域：订单同步 → 订单事实 → 退款事实 → 发布事件
                ↓
业绩域：订单事实 + 映射 + 配置 → 最终归属 → 提成 → 冲正 → 汇总
                ↓
分析模块：只读汇总 → Dashboard / 报表 / 导出
```

## 模块边界

| 层 | 职责 |
| --- | --- |
| 前端 | UI、交互、表单轻量校验、接口调用、错误提示 |
| 后端 | 核心业务规则、权限、状态机、幂等、审计、持久化事实 |
| SDK/Gateway | 第三方接口封装、鉴权、参数转换、签名、错误码适配、响应标准化 |
| 数据库 | 持久化事实、约束关键一致性、支撑查询 |
| 测试 | 核心链路、异常分支、权限边界、数据一致性、回归风险 |

## 不进入 V1 的闭环

- 不要求完整实现旧 V2.2 中所有运营自动化
- 不把旧 Python / Celery 定时任务作为当前业务闭环
- 更复杂的异步工作流、MQ 编排和跨服务拆分进入后续阶段
