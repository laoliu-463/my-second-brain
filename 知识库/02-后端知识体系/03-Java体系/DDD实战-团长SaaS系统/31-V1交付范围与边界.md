# V1 交付范围与边界

## 概述

V1 是抖音团长 SaaS 的最小可交付闭环。范围划定的核心原则：**当前代码 > 当前 V1 文档 > 旧 V2.2 文档**，遇到冲突必须写 ADR，不能靠猜测。

## V1 必做

- 用户域：登录、角色、组织、菜单、`self/group/all` 数据范围
- 配置域：配置读取、变更、审计，不执行业务规则
- 商品域：商品库、活动商品同步、转链、`pick_source_mapping` 落库
- 达人域：达人资料、标签、地址、跟进、渠道关系
- 寄样域：申请、审批、发货、交作业（以订单已同步事件为证据）
- 订单域：订单同步、退款事实、归因输入，只存事实不算提成
- 业绩域：最终归属、提成、冲正、双轨金额计算
- 分析模块：Dashboard、报表、只读汇总，不重算归属
- test / real-pre 验收必须有脚本、API/SQL、证据路径
- real-pre 验收不得使用 mock 数据冒充真实闭环

## V1 简化

- 事件优先用 Spring 本地事件 + Outbox，不强制引入 MQ
- 第三方接口按 P0 链路优先，缺权限/Token/样本的分支保留 BLOCKED 证据
- 看板以已落库事实为准，复杂 BI 能力后置
- 部署以 Docker Compose test / real-pre 可验证环境为主

## V1 不做

- 不把 FastAPI / Celery / Python 爬虫写成当前运行事实
- 订单域不计算提成、不应用独家覆盖
- 配置域不执行具体业务规则
- 分析模块不重算业绩归属
- 不用 mock 数据伪装 real-pre 闭环
- 不因旧 V2.2 文档存在而扩大本轮交付范围

## V2 预留

- 完整 MQ 化、跨服务拆分、分布式一致性治理
- 完整达人采集、外部平台爬取策略
- 复杂财务结算、商家结算、多账期治理
- 生产级运维体系、告警、容量、灰度
- 旧 V2.2 中未进入 V1 的完整运营平台能力

## 冲突处理规则

| 原则 | 说明 |
| --- | --- |
| 当前代码优先 | 可运行配置 > 旧文档描述 |
| V1 优先于旧 V2.2 | 当前文档 > 历史归档 |
| 冲突必须写 ADR | 不能自行猜测业务规则 |

## 验收边界

| 验收项 | 证据要求 |
| --- | --- |
| V1 P0 | `npm run e2e:v1-p0`、API/SQL 证据、截图或报告 |
| real-pre | `npm run e2e:real-pre:p0`、真实 Token、真实接口响应、证据索引 |
| 后端回归 | Maven 测试结果或明确未运行原因 |
| 前端回归 | 前端构建 / E2E / 浏览器证据 |
| 文档重构 | 文件结构、范围标记、归档索引、冲突清单 |
