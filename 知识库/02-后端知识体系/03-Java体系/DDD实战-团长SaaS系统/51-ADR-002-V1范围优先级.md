# ADR-002 V1范围优先级

## 状态

**已采纳**，后续发现冲突继续追加

## 背景

- 仓库存在旧 V2.2 完整方案和多个专项记录，覆盖范围大于当前 V1 交付
- 本轮目标是 Harness Engineering 风格文档重构，不重新发明需求，不扩大业务范围
- 用户明确要求 V1 范围优先于旧 V2.2 完整方案

## 决策

- 当前事实优先级：**当前代码和可运行配置 > 当前 V1 文档 > 旧 V2.2 文档**
- 发现冲突时，不自行猜测业务规则，先记录冲突、证据和待确认问题
- 旧 V2.2 中未进入 V1 的能力放入 `V2 预留` 或 `历史归档`

## 已发现冲突清单

| 冲突 | 证据 | 当前处理 |
| --- | --- | --- |
| 旧文档包含 FastAPI/Celery/Python 爬虫口径 | 旧七域和专项文档 | 仅归档为历史背景，当前事实写 Spring Boot |
| 旧领域文档中订单同步提及 Celery | 旧订单域文档 | 当前订单同步按 Spring Boot/Gateway/Job 口径 |
| 旧达人文档包含 `Python+requests+fake-useragent` | 旧达人域文档 | 当前达人信息通过系统内资料和 Gateway |
| real-pre profile 存在 `real` 与 `real-pre` 口径漂移 | `.env.real-pre` | 启动前以实际 env、compose、日志为准 |
| 旧文档 local-mock 与 real-pre 描述混杂 | 旧主干和专项文档 | test/mock 与 real-pre 分开 |
| 订单域与业绩域边界在旧方案中容易混淆 | 七域文档 | 订单只存事实；业绩负责最终归属 |
| 分析模块可能被误写为重算业绩 | 旧 dashboard 口径 | 分析模块只读汇总表 |
| 物流、达人第三方接口可能缺权限包 | 旧 real-pre 记录 | BLOCKED 必须保留真实证据 |

## 待人工确认

- `.env.real-pre` 与 `.env.real-pre.example` 的 profile 名称是否统一为 `real-pre`
- OpenAPI Spec 是否需要重新从服务端刷新
- quick sample 在 V1 中是否只作为内部寄样入口
- 物流和达人第三方接口在 V1 P0 中的最低通过标准
