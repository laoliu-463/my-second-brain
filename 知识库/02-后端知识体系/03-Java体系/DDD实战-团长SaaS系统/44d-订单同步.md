# 订单同步

## 概述

从抖店侧同步订单和退款事实，落入订单域。订单同步后发布订单已同步事件，供寄样域和业绩域消费。

## 核心事实

- 订单域只存事实，不算提成，不应用独家覆盖
- 订单同步必须具备幂等、时间窗口、错误记录和真实响应证据
- 旧 Celery 口径不是当前运行事实

## 数据流

1. 管理端或任务触发订单同步
2. Gateway 使用真实 Token 调用订单接口
3. 订单域保存订单事实和退款事实
4. 订单域发布订单已同步/退款事实已同步事件
5. 寄样域判断交作业完成，业绩域计算归属和冲正

## 验收证据

- 第三方订单接口请求/响应摘要
- 订单表、订单明细、退款表 SQL/API 证据
- 同步日志包含时间窗口、数量、成功/失败摘要
- 业绩域结果单独验收，不能用订单表替代

## 明确不做

- 不在订单同步时直接写最终提成
- 不用 mock 订单证明 real-pre 订单回流
