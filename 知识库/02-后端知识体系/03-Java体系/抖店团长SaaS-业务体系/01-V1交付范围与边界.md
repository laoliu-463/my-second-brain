# V1交付范围与边界

## 概述

V1 是抖音团长 SaaS 的最小可交付闭环。范围划定原则：**当前代码 > 当前 V1 文档 > 旧 V2.2 文档**，遇到冲突必须写 ADR，不能靠猜测。

## V1 必做

- 用户域：登录、角色、组织、菜单、`self/group/all` 数据范围
- 配置域：配置读取、变更、审计，不执行业务规则
- 商品域：商品库、活动商品同步、转链、`pick_source_mapping` 落库
- 达人域：达人资料、标签、地址、跟进、渠道关系
- 寄样域：申请→审批→发货→交作业（以订单已同步事件为证据）
- 订单域：订单同步、退款事实、归因输入，只存事实不算提成
- 业绩域：最终归属、提成、冲正、双轨金额计算
- 分析模块：Dashboard、报表、只读汇总，不重算归属
- test / real-pre 验收必须有脚本、API/SQL、证据路径
- real-pre 验收不得使用 mock 数据冒充真实闭环

## V1 简化

- 事件优先用 Spring 本地事件 + Outbox，不强制引入 MQ
- 第三方接口按 P0 链路优先，缺权限/Token/样本的分支保留 BLOCKED 证据
- 看板以已落库事实为准，复杂 BI 能力后置

## V1 不做

- 不把 FastAPI / Celery / Python 爬虫写成当前运行事实
- 订单域不计算提成、不应用独家覆盖
- 配置域不执行具体业务规则
- 分析模块不重算业绩归属
- 不用 mock 数据伪装 real-pre 闭环

## V2 预留

- 完整 MQ 化、跨服务拆分
- 完整达人采集、外部平台爬取策略
- 复杂财务结算、商家结算、多账期治理
- 生产级运维体系
