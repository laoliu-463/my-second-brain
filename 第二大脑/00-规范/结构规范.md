# 结构规范.md

> 第二大脑硬约束的来源。所有 .md / 脚本生成前先读此文件。
> 自动化校验见 `07-脚本/line_guard.py`。

## 1. 五条硬约束

| 约束 | 上限 | 校验工具 |
|---|---:|---|
| 总文件数 | ≤ 50 | line_guard.py |
| 单文件行数 | ≤ 200 | line_guard.py |
| 一级子目录数 | ≤ 10 | line_guard.py |
| 每目录文件数 | ≤ 10 | line_guard.py |
| 目录命名 | 编号-中文名 | 人工 + lint |

## 2. 目录命名规则

```text
00-规范
01-状态
02-项目总览
03-领域知识
...
```

**禁止**：`00-schema`、`01-state`、`02-core` 等英文数字编号。

## 3. 文件命名规则

| 类型 | 命名 | 例子 |
|---|---|---|
| 普通页面 | 中文 .md | `当前状态.md` |
| 顶级入口 | 中文 .md | `索引.md`、`日志.md` |
| Agent 协议 | 英文 | `AGENTS.md` |
| 项目说明 | 英文 | `README.md` |
| 动态槽位 | 编号-中文 | `任务-001.md`、`报告-002.md` |
| 脚本 | 英文 | `line_guard.py`、`brain_lint.py` |

## 4. 目录布局

```text
第二大脑/
├─ 00-规范/         结构、页面、安全 3 文件
├─ 01-状态/         当前、决策、债务、问题、来源 5 文件
├─ 02-项目总览/     项目概览、闭环、地图、环境、验收、术语 6 文件
├─ 03-领域知识/     8 个领域业务合同 8 文件
├─ 04-运行流程/     吸收、查询、健康、生命周期 4 文件
├─ 05-任务管理/     总表、队列、模板 + 6 动态槽 9 文件
├─ 06-报告证据/     索引、模板 + 4 动态槽 6 文件
├─ 07-脚本/         3 个 Python 工具
└─ 08-模板/         2 个页面模板
```

## 5. 索引规则

- `索引.md` 必须覆盖所有 .md 文件
- 每个目录可有 index，但 50 文件上限下**不强制**
- 跨目录跳转用 Obsidian wiki link 形式，如 `[[目录/文件]]`（外层方括号是模板占位符）

## 6. 资料源规则

- 原始资料不复制进第二大脑
- 仅在 `01-状态/资料来源.md` 登记路径、摘要、状态
- 报告原文归项目侧 `harness/reports/` 或本地 `06-报告证据/报告-*.md`

## 7. 违规处置

| 违规 | 动作 |
|---|---|
| 总文件 > 50 | 立即 GC；归档非核心 |
| 单文件 > 200 行 | 拆分为正文 + 引用；或提炼摘要 |
| 目录 > 10 个 | 合并子目录 |
| 单目录 > 10 文件 | 拆出子目录或归档 |
| 命名不规范 | 改名（不破坏链接） |
