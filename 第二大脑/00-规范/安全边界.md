# 安全边界.md

> 第二大脑 Agent 的禁止操作范围。
> 与 `D:\Projects\SAAS\harness\rules\governance\forbidden-scope.md` 联动。

## 1. 绝对禁止

1. **写业务代码**：不修改 `D:\Projects\SAAS\backend/`、`frontend/`
2. **改业务主源**：`docs/01-V1交付范围与边界.md`、`docs/决策/ADR-*.md` 不动
3. **执行数据库写**：drop / truncate / update / insert 全部禁止
4. **重启容器**：`docker compose restart` 等禁止
5. **远端部署**：`deploy-remote.ps1` 等禁止
6. **git push**：包括 `git push --force` 和 `git push` 默认
7. **混批 commit**：`git add .` 禁止，必须明确文件
8. **把 mock 当 real-pre**：mock 数据只能用于 test
9. **把 PENDING/BLOCKED 写成 PASS**
10. **写密钥/凭证**到任何 .md：禁止 token、password、cookie、private key

## 2. 高风险操作（需二次确认）

## 4. 失败模式

| 模式 | 后果 | 立即动作 |
|---|---|---|
| 未读 FORBIDDEN_SCOPE 就行动 | 越界 | 立即停 |
| 未生成证据就声明完成 | 虚假完成 | 立即停 |
| 脏工作区未登记就开新任务 | 脏状态 | 立即停 |
| 同一 Agent 既生成又验证 | 偏差 | 引入新视角 |
| 把归档源当成事实源 | 时间错位 | 立即停，回源 |

## 5. 与项目侧 FORBIDDEN_SCOPE 的关系

项目侧有完整 forbidden-scope（170+ 行），本文件为**摘要+第二大脑特化**。
冲突时：
- 第二大脑操作 → 以本文件为准
- 业务/项目问题 → 以项目侧 forbidden-scope 为准
