# 业务闭环.md

> V1 三条主链的业务闭环定义、关键节点、验收口径。
> 详细：`D:\Projects\SAAS\docs\02-业务闭环总览.md` + `docs/流程/*.md`。

## 渠道链

```
认领达人 → 商品库选品 → 复制讲解/转链 → 寄样申请 → 订单同步 → 渠道业绩 → 寄样自动完成
```

**关键节点**：
- 转链成功 → 落 `pick_source_mapping`
- 订单同步 → 写 `orders.pick_source`、`default_channel_id`、`default_recruiter_id`
- 寄样自动完成 → 订单已同步事件触发

## 招商链

```
同步活动 → 活动商品入库 → 商品上架 → 审核寄样 → 订单同步 → 招商业绩
```

**关键节点**：
- 活动商品上游推广中状态 → 自动入库
- `selected_to_library=true`
- 招商链归属来自 `default_recruiter_id`

## 管理链

```
用户角色 → 数据范围 → 规则配置 → 各领域读取配置 → 权限生效
```

**关键节点**：
- 数据范围统一 `self / group / all`
- 业务域只消费用户域输出的数据范围
- 权限冲突回到 `docs/07-权限与数据范围.md`

## 真实闭环判定

**订单入库 ≠ 业务闭环**。真实闭环必须同时验证：

- [ ] `orders.pick_source` 不为空，或存在可解释的 NATIVE / `colonel_buyin_id` 映射证据
- [ ] `orders.default_channel_id` 不为空
- [ ] `orders.default_recruiter_id` 不为空
- [ ] `sample_requests` 能从待交作业变为已完成
- [ ] `performance_records` 正确生成
- [ ] 看板 / 业绩归属正确

## 跨链依赖

```
config ─┐
        ├─→ order ─→ performance ─→ analysis
product ┤    ↑
talent  ┘    │
             └─ sample（订单已同步事件）
user ────────→ 所有域（数据范围）
```

## 闭环状态机

- `NOT_STARTED` / `IN_PROGRESS` / `PASS` / `PENDING` / `BLOCKED_BY_SAMPLE` / `BLOCKED_BY_EXTERNAL` / `FAILED` / `RISK_ACCEPTED`

**非法状态**：把任一非 PASS 状态包装为 PASS。
