# 验收门禁.md

> V1 验收必须满足的 G0-G4 五个门禁。
> 详细：`D:\Projects\SAAS\harness\rules\governance\COMPLETION_GATES.md` + `completion-gates-detail.md` + `completion-gates-git.md`。

## Gate 0 — 范围与边界

- 命中域、流程、ADR 是否明确
- FORBIDDEN_SCOPE 是否已读
- 未声明的越界行为 = 0

**未过**：不允许进入 G1

## Gate 1 — 文档同步

- 修改业务规则 → `docs/领域/*.md` 同步
- 修改部署 / 端口 / 开关 → `harness/environment/*` 同步
- 修改决策 → `harness/state/DECISIONS.md` + 新 ADR
- 修改 Harness 规则 → `harness/HARNESS_CHANGELOG.md`

**未过**：不允许进入 G2

## Gate 2 — 自测与构建

- Java：`cd backend && mvn test` 通过
- 前端：`cd frontend && npm run build` 通过
- 静态检查：TS / ESLint / Prettier 通过
- 单测覆盖率 ≥ 80%（V1 最低）

**未过**：不允许进入 G3

## Gate 3 — 真实上游验证（real-pre 任务）

- `npm run e2e:real-pre:p0:preflight` 通过
- 真实订单 / 商品 / 达人样本 ≥ 1
- 渠道归因三环：转链 → 订单 → 业绩 都存在真实样本
- 部署结论严格按 `docs/验收/real-pre联调手册.md` 口径

**未过**：不允许进入 G4

## Gate 4 — 证据生成

至少 1 类，缺一即不可 PASS：

1. **脚本输出**：`mvn test` / `npm run e2e:v1-p0` 完整日志
2. **API/SQL 对账**：cURL 输出 + SQL 行数 / 字段对比
3. **文件路径**：截图 / trace / 日志 / 文档索引路径

证据必须登记到 `docs/验收/验收证据索引.md` 或本任务报告。

## docs-only 例外

`Scope=docs` 可跳过构建、容器重启和业务 E2E，但必须：

- 执行 `safety-check.ps1`
- 执行 `collect-evidence.ps1`
- 执行 `new-retro.ps1`
- 报告中写明构建 / 重启 / 健康检查未执行

## 禁止结论

- 未验证不得写 PASS
- `BLOCKED` / `PENDING` / `PARTIAL` 不能写成 PASS
- 脚本失败后不能声明成功
