# 资料吸收流程.md

> 新资料如何进入第二大脑/。所有"我刚发现一个文件/链接/报告"先走此流程。

## 1. 触发条件

- 用户说"吸收资料"、"整理文件"、"归档到知识库"
- 发现新源文件（PDF、报告、链接、CSV）
- 收到新 ADR / 决策

## 2. 步骤

### Step 1：判断分类

| 资料类型 | 目标位置 |
|---|---|
| 项目业务文档 | `01-状态/资料来源.md` 登记 |
| harness 报告 | `01-状态/资料来源.md` 登记 |
| 业务合同 / 8 域 | 沉淀到 `03-领域知识/<域>.md` |
| 决策 / ADR | 沉淀到 `01-状态/已确认决策.md` |
| 当前状态变化 | 沉淀到 `01-状态/当前状态.md` |
| 待解决问题 | 沉淀到 `01-状态/待确认问题.md` |
| 任务卡 | 沉淀到 `05-任务管理/任务-*.md` |
| 报告 / 证据 | 沉淀到 `06-报告证据/报告-*.md` |

### Step 2：提炼 vs 复制

- **不复制原文**：第二大脑只沉淀摘要、结论和证据路径
- **只登记路径**：源位置写明，必要时给摘要
- **关键结论沉淀**：业务合同、状态、决策、风险 → 摘要进第二大脑
- **详细原文**：归项目侧或 vault 其他位置

### Step 3：写摘要

每个沉淀的页面使用 `00-规范/页面规范.md` 对应模板：
- 状态页 → 30-80 行
- 领域页 → 50-100 行
- 总览页 → 30-80 行
- 任务页 → 20-50 行
- 报告页 → 30-100 行

### Step 4：更新索引

- 新建文件后，**必须**在 `索引.md` 对应章节添加链接
- 否则 `brain_lint.py` 报告 MISSING_IN_INDEX

### Step 5：日志追加

- 在 `日志.md` 追加一行：`HH:MM` + 动作 + 文件路径
- 旧内容不删，append-only

### Step 6：健康检查

- 跑 `python 第二大脑/07-脚本/line_guard.py`
- 跑 `python 第二大脑/07-脚本/brain_lint.py`
- 两个都 PASS 才算完成

## 3. 异常处理

| 异常 | 处置 |
|---|---|
| 资料 > 200 行 | 拆为正文 + 引用；或只放摘要 + 源路径 |
| 资料跨多域 | 拆为多页，根页只放索引 |
| 资料含密钥 | 立即丢弃原文 + 报告用户 |
| 资料与现有重复 | 合并或标记 superseded |
| 资料过期 | 标 `[DEPRECATED]` + 归档原因 |

## 4. 完成标志

- `索引.md` 已更新
- `日志.md` 已追加
- `line_guard.py` PASS
- `brain_lint.py` PASS
- 用户已确认
