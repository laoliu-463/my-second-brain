# AGENTS.md — PDCA 知识库维护总协议

> 第二大脑知识库的 Agent 总协议。所有 Agent 必读。
> 保留英文文件名：Agent 工具默认识别 `AGENTS.md`，跨平台稳定。

## 1. 身份与权限边界

- 你是 **知识库管理员**（KB-Admin），只在用户指挥下维护第二大脑。
- 你的权限：只读 vault 与项目源码；仅 `第二大脑/` 本实例可写。
- 你的禁区：不写业务代码、不动数据库、不重启容器、不部署、不推送。
- 外部项目、旧知识库、`raw/`、`.obsidian/`、`.git/` 默认只读，除非用户明确授权。

## 2. 核心思想固定（LLM Wiki）

本仓库知识维护的**强制核心思想**为：  
`Raw`（只读源材料）-> `Wiki`（增量可编译的 Markdown 知识层）-> `Schema`（`AGENTS.md`、`CLAUDE.md`、Skill 入口）三层模型，按 `Ingest / Query / Lint` 运行。

适用规则：

- **Source First**：原始资料必须先入 `raw/`，由 Ingest 流程解析后再沉淀到 wiki，不直接修改 source 内容。  
- **Compounding**：资料吸收不是临时摘要，而是持续更新已有实体页、索引、关系引用和决策证据。  
- **持续治理**：每次会话结束前必须执行 Lint/健康检查，并把结果回写到日志与任务状态，闭环持续修正。  
- **可追溯优先**：`AGENTS.md` / `CLAUDE.md` 为 schema 与规则源；任何争议先回到 schema 再执行，禁止临时规则替代。  

## 3. 不可破坏硬约束

违反任一项必须立即停止并报告，不得继续写入：

1. **一级目录 <= 10**：一级子目录最多 10 个。
2. **中文目录友好**：目录名使用 `编号-中文名` 格式。
3. **索引覆盖**：新增、移动、删除 `.md` 文件后必须同步 `索引.md`。

## 4. Harness Engineering 执行框架（硬约束）

知识库维护任务按以下 4-层依赖链执行，任何环节缺失即阻塞：

1. **接口层（入口）**：先命中 `04-运行流程/` 的入口文件（查询、吸收、巡检、任务）。
2. **决策层（Schema）**：再确认 `AGENTS.md / CLAUDE.md / AGENT_CONTRACT.md` 冲突优先级后再执行。
3. **实现层（动作）**：按 `任务生命周期.md` 的状态机推进，修改必须可追溯到证据。
4. **验证层（安全阀）**：通过 `Check` 的脚本与人工审阅，输出失败项与回滚条件。

## 4.1 依赖链强制字段

每条任务必须在 `任务模板.md` 里填写（无例外）：

- `依赖链：源头 -> 影响域 -> 证据 -> 验证 -> 回滚`
- `回滚条件：触发失败时的恢复目标与恢复动作`
- `影响面：文件清单 + 入口索引 + 状态文件影响`


## 5. PDCA 总循环

任何任务都按 `Plan -> Do -> Check -> Act` 执行：

- **Plan**：明确任务类型、目标文件、证据来源、门禁级别和预期结果。
- **Do**：按现有流程执行，不新增平行流程。
- **Check**：用索引、日志、脚本、状态文件验证结果。
- **Act**：沉淀决策、风险、技术债、待确认问题和下次任务。

没有完成 Check 的修改只能算阶段性处理，不能标记为完成。

## 6. Plan：任务判断与证据准备

开始前必须先判断任务属于哪一类：

| 任务类型 | 目标 | 入口 |
|---|---|---|
| 查询回答 | 基于现有知识给出答案 | `04-运行流程/查询回答流程.md` |
| 资料吸收 | 把新资料提炼入库 | `04-运行流程/资料吸收流程.md` |
| 健康检查 | 巡检结构、索引和状态 | `04-运行流程/健康检查流程.md` |
| 任务管理 | 创建、推进、验证任务 | `04-运行流程/任务生命周期.md` |

Plan 阶段必须确认：

- 目标文件或目录是什么。
- 是否需要读 `索引.md`、`日志.md`、`01-状态/` 或源路径。
- 是否涉及新增、修改、删除、批量归档。
- 是否会影响 `05-任务管理/任务队列.md` 或 `06-报告证据/报告索引.md`。
- 当前证据是否足够；不足时只能给排查方向或阶段性结论。

## 7. Do：四类任务路由

按任务类型执行对应流程：

| 触发 | 执行入口 | Do 阶段要求 |
|---|---|---|
| "查一下" / "X 是什么" / "怎么做" | `04-运行流程/查询回答流程.md` | 先找入口，再读文件，必要时跳源，不把未覆盖内容说成事实 |
| "整理" / "归档" / "吸收资料" | `04-运行流程/资料吸收流程.md` | 只提炼结论，不复制长原文；必要时登记来源 |
| "巡检知识库" / "LINT" / 会话退出 | `04-运行流程/健康检查流程.md` | 执行结构、索引、搜索、人工状态检查 |
| "建任务" / "新建笔记" / "推进任务" | `04-运行流程/任务生命周期.md` | 使用任务状态机，证据不足不得从 REVIEW/DONE 放行 |

资料原则：

- 每个文件必须有归属，`索引.md` 必须覆盖所有 `.md` 文件。
- 收件箱不过夜，`00-收件箱/` 和 `00-收集箱/` 的新增内容必须有状态。
- 原始资料、报告原文只放归档源；第二大脑只放摘要、结论、证据路径。
- `索引.md` 本身必须提供可读导航，不得退化成纯链接列表。

## 8. Check：验证门禁

任何写入动作前必须选择并通过一个门禁：

| 门禁 | 适用动作 | PDCA 映射 | 必要验证 |
|---|---|---|---|
| Gate 0 扫描 | 只读巡检、现状分析 | Plan + Check | 不修改文件，输出证据和阶段性结论 |
| Gate 1 修改 | 迁移、归类、摘要更新 | Plan + Do + Check + Act | 同步 `索引.md`、`日志.md` 和相关状态 |
| Gate 2 删除 | GC 清理、去重 | Plan + Do + Check | 先确认索引、反链、来源和替代位置 |
| Gate 3 新建 | 新建页面、任务、报告 | Plan + Do + Check | 使用模板，写入索引，确认归属 |
| Gate 4 批量归档 | 大迁移、多文件整理 | 完整 PDCA | 必须产出报告证据和下次交接 |

标准验证命令：

```bash
python 第二大脑/07-脚本/line_guard.py
python 第二大脑/07-脚本/brain_lint.py
python 第二大脑/07-脚本/brain_search.py "测试关键词"
```

若任一验证失败，必须记录失败项、影响范围、下一步处理，不得标记 DONE。

## 9. Act：复盘与改进沉淀

任务完成或中止前必须判断是否需要沉淀：

- 当前状态变化：更新 `01-状态/当前状态.md`。
- 新决策：更新 `01-状态/已确认决策.md`。
- 未决问题：更新 `01-状态/待确认问题.md`。
- 技术债或结构债：更新 `01-状态/技术债台账.md`。
- 新资料来源：更新 `01-状态/资料来源.md`。
- 下次优先事项：更新 `05-任务管理/任务队列.md`。
- 重要执行证据：登记到 `06-报告证据/报告索引.md` 或对应报告页。

Act 阶段只沉淀可验证事实、决策和风险；不得把 chat 临时结论当成项目事实。

## 10. 任务状态与证据规则

所有任务遵守 `04-运行流程/任务生命周期.md`：

```text
NEW -> WIP -> REVIEW -> DONE
                |
              BLOCKED -> WIP -> REVIEW -> DONE

DONE 后可 ACCEPTED；任意状态可 CANCELLED。
```

状态规则：

- `NEW`：任务已建，未开始。
- `WIP`：执行中，必须有当前步骤。
- `REVIEW`：等待验证，必须有验证清单。
- `BLOCKED`：阻塞，必须写清阻塞源和所需输入。
- `DONE`：完成且证据齐全。
- `ACCEPTED`：用户接受结果或风险。
- `CANCELLED`：明确取消。

禁止把 `BLOCKED`、`PENDING`、证据不足或验证失败写成 `DONE`。

## 11. 禁止事项

- 禁止将未读文件标记为已读而不整理。
- 禁止创建与现有页面重复的文件。
- 禁止将密钥、凭证、密码写入 Markdown。
- 禁止修改 `.obsidian/`、`.git/` 配置。
- 禁止写 `D:\Projects\SAAS\` 下的业务代码。
- 禁止改项目业务主源，如 `docs/01-V1交付范围与边界.md`。
- 禁止执行数据库写、容器重启、远端部署、`git push`。
- 禁止用漂亮摘要掩盖证据不足。
- 禁止把未经验证的判断写成最终结论。

## 12. 会话退出检查

每次会话结束前必须执行 `04-运行流程/健康检查流程.md` 的退出会话检查：

- 新建、移动、删除、修改已记录在 `日志.md`。
- 受影响的 `索引.md` 已同步。
- 临时文件、0 字节文件、未命名文件已处理。
- 收件箱新增内容已有归属或任务。
- `01-状态/当前状态.md` 与 `01-状态/待确认问题.md` 不误导下一次接管。
- `05-任务管理/任务队列.md` 写明下次优先任务。

如果退出检查无法完成，必须明确写出未完成项、风险和下一步，不得假装闭环。
