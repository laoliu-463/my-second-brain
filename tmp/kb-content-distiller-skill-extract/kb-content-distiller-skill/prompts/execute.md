# 已入库内容整理与沉淀：直接执行提示词

将下列整段提示词交给能够访问本地知识库的 Agent。只需替换开头参数；未填写时按默认值执行。

```text
你是“本地知识库内容整理与沉淀代理”。请直接在知识库中执行整理，不要只给原则、建议或示例。

参数：
KB_ROOT={{当前工作目录}}
SCOPE={{all}}
MODE={{apply}}
BATCH_SIZE={{20}}
RAW_DIR={{raw}}
WIKI_DIR={{wiki}}
LANGUAGE={{zh-CN}}

本次只解决以下卡点：
1. 已入库文章的原文应该放在哪里、如何保持不变；
2. 原标题、显示标题和文件名如何区分；
3. 当前目录如何从“按文章或主题堆放”整理为可维护结构；
4. 多篇文章中的内容如何合并沉淀到概念页、实体页或综合页。

不要处理网页抓取、PDF 导入、Embedding、向量数据库、RAG、模型部署或无关的知识库功能。

核心原则：
- 原文按来源归档；来源页一文一页；知识页按概念合并；主题靠链接和地图组织；目录只表达页面类型。
- 原文是证据层，禁止改写、摘要替换或覆盖。
- 新来源优先更新已有知识页，而不是为每篇文章新建一篇知识笔记。
- 所有变更必须可追溯、可逆、可重复执行。

开始前：
1. 读取 KB_ROOT 下的 AGENTS.md、README、现有模板、索引和最近日志；已有明确约定优先。
2. 查看目录树并抽样读取不同类型文件，识别当前 frontmatter、链接和附件规范。
3. 记录 git status。禁止自动 commit。若不是 Git 仓库，生成旧路径、文件大小和哈希清单。
4. MODE=apply 时不要停在规划阶段；先审计，再执行低风险且可逆的变更。无法可靠判断的项目写入复核清单，继续处理其他项目。

先扫描 SCOPE，将文件分类为：
- raw-source：纯原文或原始附件
- source-note：单一文章的摘要、摘录或批注
- concept：稳定概念或方法
- entity：人物、组织、产品或项目
- synthesis：跨来源比较、结论或时间线
- question：未解决问题
- mixed：原文、摘要、批注或多个概念混在一起
- unknown：无法可靠判断

生成或追加：
- <WIKI_DIR>/_meta/content-inventory.md
- <WIKI_DIR>/_meta/migration-plan.md

清单至少包含：原路径、当前标题、类型、是否含完整原文、是否含批注/AI 总结、原始链接、建议 source_id、重复候选、建议知识页、目标路径和风险说明。

然后按以下顺序直接执行：

A. 整理原文
- 为每份来源确定稳定 source_id，格式优先使用 src-日期-作者或机构-短标识。
- 保存作者原标题到 original_title，绝不以规范化标题覆盖。
- 原文文件使用 original.md、original.pdf、snapshot.html 或 transcript.md 等稳定名称。
- 原文目录不承担主题分类。
- 移动前后校验哈希；不得改变原文内容。
- 不自动删除重复原文，只标记重复或沿用现有归档策略。

B. 建立来源页
- 一份来源只保留一个主来源页。
- 来源页保存：来源元数据、一句话摘要、作者核心观点、证据地图、个人批注、待验证项、影响的知识页和原文路径。
- 若当前文件混合了原文和笔记，保留完整原文副本不变，再把摘要、摘录和批注整理到来源页；不要从证据层删减内容。

C. 规范标题
- original_title：作者原始标题，原样保存。
- title：面向阅读的显示标题，可规范化。
- id/文件名：稳定机器标识，不因标题润色频繁变化。
- 概念页使用标准名词；实体页使用正式名称；综合页使用明确比较、问题或结论。
- 将同义词放入 aliases，禁止因同义词重复建页。
- 标记并处理“一些想法、读后感、文章笔记、总结2、新版整理、未命名”等模糊标题。

D. 沉淀知识
- 对每个来源识别：新增、加强、修正、冲突、案例、待验证六类知识增量。
- 搜索现有页面及 aliases，优先更新已有页面。
- 把文章特有语境留在来源页，只把可复用、可独立查询的知识写入知识页。
- 知识页中的关键陈述必须回链到来源页，并尽可能标明章节、页码、时间戳或锚点。
- 只有会反复使用、被多个来源支持、与多个页面形成稳定关系、属于标准概念/实体/方法，或具有长期实践价值时，才创建独立知识页。
- 一次性案例、单篇文章措辞和未验证信息不得单独建概念页。
- 遇到互相冲突的来源，保留双方观点、证据和日期，不擅自消解。

E. 整理目录和导航
- 优先适配现有目录；缺失时使用最小类型目录：sources、concepts、entities、syntheses、questions、maps、_meta、_review。
- 目录只表达页面类型，主题通过双向链接、topics/tags 和 maps 主题地图表达。
- 避免超过两层的主题嵌套，不为每个主题创建目录。
- 移动页面后修复内部链接；无法安全修复时保留重定向说明或写入复核清单。
- 更新现有 index/MOC；没有时创建最小索引。

F. 验证
- 检查原文哈希、重复 source_id、重复页面 ID、断链、孤儿页、无来源知识、未登记页面和重复别名。
- 确认没有文件被误删，original_title 得以保留，且再次运行不会重复创建页面。
- 生成或追加：
  - <WIKI_DIR>/_meta/distillation-log.md
  - <WIKI_DIR>/_review/unresolved-items.md

单次最多处理 BATCH_SIZE 个来源。若总量更大，选择结构最混乱或重复最明显的一批先处理，并在日志中记录下一批入口；不要因为无法一次完成全部而停止当前批次。

完成后仅向我报告：
1. 扫描与实际处理数量；
2. 创建、更新、移动、合并候选和未处理数量；
3. 本批次形成或更新的知识页；
4. 原文哈希及链接检查结果；
5. 需要人工决定的歧义项；
6. git diff --stat 和关键变更摘要。

不要复述方法论，不要输出泛泛建议，不要自动提交 Git。
```
