# 已入库内容整理与沉淀 Skill

本 Skill 只解决一个问题：**把已经入库、但仍以文章为中心或结构混乱的内容，整理成可持续维护的本地知识库。**

核心原则：

> 原文按来源归档；来源页保留文章语境；知识页按概念合并；主题用链接和地图组织；目录只表达页面类型。

## 适用范围

处理：

- 原文、摘要、批注混在同一文件中
- 文章标题直接充当知识页标题
- 同一概念分散在多篇文章笔记中
- 目录按主题深层嵌套，文章难以归类
- 重复页面、同义标题、失效链接与孤儿页
- 已入库内容缺乏来源追溯和持续更新机制

不处理：

- 抓取或导入新的网页、PDF、音视频
- 向量数据库、RAG、Embedding 或搜索系统搭建
- 模型选择与本地模型部署
- 未经要求的大规模内容改写

## 默认输入

从用户指定的知识库根目录开始。若未明确指定，则使用当前工作目录。

可选参数：

```text
KB_ROOT=<知识库根目录，默认当前目录>
SCOPE=<指定目录、文件列表或 all，默认 all>
MODE=apply             # apply | plan
BATCH_SIZE=20          # 单次最多处理的来源数量
RAW_DIR=raw
WIKI_DIR=wiki
LANGUAGE=zh-CN
```

`MODE=apply` 时先审计，再直接实施低风险、可逆变更；歧义项进入复核清单，不因个别歧义停止整个批次。

## 强制边界

1. 先读取根目录中的 `AGENTS.md`、`README.md`、现有模板及索引；已有明确规则优先于本 Skill 的默认目录名。
2. 原文是证据层，禁止重写、摘要替换或覆盖。移动原文时必须保证内容哈希不变。
3. 不自动删除文件。重复项只标记，或移动到用户已有的归档区；没有归档约定时保持原位。
4. 修改前记录 `git status`。修改后输出 `git diff --stat` 和关键差异。禁止自动提交。
5. 若目录不是 Git 仓库，先生成文件清单、旧路径映射和哈希记录，再进行移动。
6. 文件移动后必须修复内部链接；无法安全修复时保留重定向说明页或列入复核清单。
7. 不把推断写成事实。所有知识性陈述都应能回溯到来源页及原文位置。
8. 整理过程必须幂等：再次运行不得重复创建同一来源页、知识页或日志条目。

## 标准页面层级

```text
原文 Raw Source
    ↓
来源页 Source Note：这篇资料说了什么
    ↓
知识页 Knowledge Note：这个概念综合来看是什么
    ↓
综合页 Synthesis：多个概念或来源能得出什么结论
```

### 1. 原文

- 一份来源对应一个稳定 `source_id`。
- 保留 `original_title`、作者、原始链接、发布日期、采集日期和原文路径。
- 原文文件可统一命名为 `original.md`、`original.pdf`、`snapshot.html` 或 `transcript.md`。
- 原文目录不承担主题分类。

推荐 `source_id`：

```text
src-<发布日期或采集日期>-<作者或机构>-<短标识>
```

示例：

```text
src-20260404-karpathy-llm-wiki
```

### 2. 来源页

- 一篇原文对应一个来源页。
- 保存文章摘要、核心论点、证据地图、个人批注、待验证项及其影响的知识页。
- 来源页不是最终知识终点。

### 3. 知识页

- 按可独立查询的概念、实体或方法组织，不按文章组织。
- 新来源优先更新已有知识页。
- 知识页应综合多个来源，并区分事实、观点、案例、推断和争议。

### 4. 综合页

- 用于跨来源比较、决策、时间线、因果关系和阶段性结论。
- 标题应体现明确问题或结论。

## 目录规则

优先适配现有结构。现有结构缺失或明显混乱时，采用最小化类型目录：

```text
raw/
  inbox/
  sources/
wiki/
  sources/
  concepts/
  entities/
  syntheses/
  questions/
  maps/
  _meta/
  _review/
```

约束：

- 目录表达“页面是什么类型”，不表达页面属于哪个唯一主题。
- 主题归属通过 `[[双向链接]]`、frontmatter topics/tags 和 `maps/` 主题地图表达。
- 避免超过两层的主题嵌套。
- 不为每个主题都创建目录。

## 标题与文件名规则

必须区分三种名称：

1. `original_title`：作者原标题，原样保留。
2. `title`：页面显示标题，可为便于理解而规范化。
3. 文件名或 `id`：稳定机器标识，不随措辞变化频繁改名。

标题规范：

- 概念页：标准名词，如 `上下文工程`
- 实体页：正式名称，如 `OpenAI`
- 综合页：明确比较或问题，如 `RAG 与编译型知识库的区别`
- 问题页：可回答的问题，如 `知识页在什么条件下应该拆分`

禁止使用：

```text
一些想法
读后感
文章笔记
总结2
新版整理
未命名
```

同义词放入 `aliases`，不要因此创建重复页面。

## 执行工作流

### 阶段 A：发现现有约定

1. 查看两到三层目录树。
2. 读取规则文件、模板、索引和最近日志。
3. 抽样检查原文、文章笔记和知识笔记。
4. 识别现有 frontmatter、链接格式和附件规则。
5. 确定应保留的现有规范及最小变更范围。

### 阶段 B：建立清单

扫描目标范围，将每个文件分类为：

```text
raw-source      纯原文或原始附件
source-note     单一来源的摘要、摘录或批注
concept         稳定概念或方法
entity          人物、组织、产品、项目
synthesis       跨来源比较、结论、时间线
question        未解决问题
mixed           原文、摘要、批注或多个概念混合
unknown         无法可靠判断
```

至少检查：

- 原始路径和当前标题
- 原始链接、作者和日期
- 是否包含完整原文
- 是否包含个人批注或 AI 总结
- 内容哈希或可用于去重的指纹
- 规范化标题后的重复项
- 可能合并到的既有知识页
- 迁移后的目标路径

将清单写入：

```text
<WIKI_DIR>/_meta/content-inventory.md
<WIKI_DIR>/_meta/migration-plan.md
```

若已有同类文件，则追加本批次章节，不覆盖历史。

### 阶段 C：整理原文与来源页

对每份来源：

1. 确定或复用稳定 `source_id`。
2. 保存原始标题为 `original_title`。
3. 保留原文内容不变；必要时移动到来源归档目录。
4. 为混合笔记拆出来源页，但不得从原文中删除内容。
5. 创建或更新唯一来源页。
6. 建立证据地图，定位到章节、页码、时间戳或原文锚点。
7. 记录旧路径到新路径的映射。

### 阶段 D：沉淀知识

逐个来源页处理“知识增量”：

```text
新增：此前不存在、值得长期保留的知识
加强：为已有结论增加证据或解释
修正：新来源改变已有表述
冲突：不同来源存在不可消解的分歧
案例：仅作为说明，不升级为核心结论
待验证：信息不足，进入问题页或复核区
```

执行顺序：

1. 搜索同义词、别名和相关现有页面。
2. 优先更新现有页面。
3. 只有满足独立性和复用价值时才创建新知识页。
4. 把文章语境留在来源页，把可复用结论写入知识页。
5. 每项知识更新建立回链到来源页。
6. 同一概念的多个文章笔记合并到一个主页面；旧页不直接删除，先转换为重定向、归档候选或复核项。

创建独立知识页需至少满足以下条件之一：

- 会被独立检索或反复使用
- 已被两个及以上来源支持
- 与多个页面形成稳定关系
- 是领域中的标准概念、实体或方法
- 对决策、实践或解释具有长期价值

仅为一次性案例、单篇文章措辞或尚不确定的信息，不创建独立知识页。

### 阶段 E：整理导航

1. 更新全库索引或现有入口页。
2. 为成熟主题创建或更新 `maps/` 页面。
3. 用链接和主题地图表达一页多主题关系。
4. 检查孤儿页、断链、重复别名和未被索引页面。
5. 不为了“看起来整齐”而建立深层目录。

### 阶段 F：验证与报告

必须验证：

- 原文内容哈希在移动前后保持一致
- 每个来源只有一个主来源页
- 页面 ID 不重复
- `original_title` 没有被规范化标题覆盖
- 移动后的内部链接有效
- 新增知识结论具备来源回链
- 没有误删文件
- 重复运行不会产生第二份相同页面

输出：

```text
<WIKI_DIR>/_meta/distillation-log.md
<WIKI_DIR>/_review/unresolved-items.md
```

最终用户报告必须包含：

- 本批次处理范围
- 创建、更新、移动和未处理数量
- 合并或疑似重复项
- 新增或更新的知识页
- 原文保护和链接检查结果
- 需要人工决定的歧义项
- `git diff --stat` 与关键变更摘要
